Android app repos you carry, not host.

Backpack is an F-Droid-like app store for Android. A repository lives in Logos Storage, announces its updates over Logos Delivery, and is nothing more than a key. There's no server to run, and you don't have to trust anyone who passes it along.

Source on GitHub How it works Design decisions
Why

A repo shouldn't depend on one web server

An F-Droid repository is a folder on a web server. If the server goes away, so does the repo. Whoever runs it can also see who downloads what. Backpack keeps what F-Droid gets right (signed indexes, pinned app signers, your own repos) and moves the content off the server:

A repo is a key

Each repository is an ed25519 key. Whatever it publishes is signed with that key, so the phone knows it's genuine no matter who delivered it.

Content is addressed by hash

The app list, the icons and the APKs are stored in Logos Storage under their content IDs. Any node that holds a CID can serve it, and nobody can change it.

Updates are announced, not polled

A new version is a tiny signed note, sent over Logos Delivery. The phone hears it live, or picks it up from the network's Store when it opens.

How it works

Three pieces, and only one is ever small enough to send around

Everything a repo contains is one of these three. They differ in size, in how they travel, and in what proves they're genuine.

1 · The update note

≈ 300 bytes

Repo key, a version number (seq) and the CID of the current index. It's signed by the repo key.

Logos DeliveryHTTPS (optional, off by default)

2 · The index

a few KB

The app list: names, descriptions, licences, versions, each APK's SHA-256, its pinned signing certificate and its CID. Also signed by the repo key.

Logos Storage

3 · APKs and icons

MBs

Fetched by CID and checked against the index before anything is installed.

Logos Storage

The phone adds a repo once, from a backpack:// link (or QR) that carries the repo key, the first index and a Storage node to start from. After that, the note does the rest.

Trust

Every byte is checked against a key you already hold

Backpack doesn't trust whoever delivered something: Delivery peers, Store nodes, Storage nodes, a web host. It only trusts the repo key from the link you opened and the signing keys of the apps already on your phone.

  • The note and the index are signed by the repo keyAn ed25519 signature over the exact bytes. Another repository, or anyone at all, can't produce one that opens with your key.
  • No going backwardsThe phone remembers the highest seq it accepted and refuses anything older, so an attacker can't replay last month's list. The index's seq must also match the note that pointed to it.
  • APKs match the indexThe downloaded file's SHA-256 must equal the signed index's.
  • App signers are pinnedThe index pins each app's signing certificate. Backpack refuses an APK signed by any other key, and refuses one whose key differs from the copy already installed.
  • Same app, different key: you're toldIf two of your repos list the same package under different signing keys, the app's page says only one of them can be the real publisher. Automatic updates only take versions signed by the key your installed copy already has.
  • F-Droid imports are verified firstMirroring an F-Droid repo starts by checking its signed index-v1.jar against the repo fingerprint, then every APK's hash and signer.

Each repo shows its publisher key, so two repositories with the same name can be told apart.

Updates

Open the app; it's already checking

Every time Backpack opens, it asks every source for the newest note and picks the highest valid seq. If the list changed, it fetches the new index from Storage. Then it updates your installed apps, unless you've switched that off.

Logos Delivery, through Loam

Backpack doesn't run its own network node. It connects to the Loam app's shared node, listens on each repo's topic and pulls the network's Store on start. A box that's always on re-sends every note twice a day, so the Store doesn't forget it. Anyone holding a note can re-send it, because it's signed.

You can see where it came from

Under each repo: #7 came from Delivery (store) · Delivery (store) ✓ #7 · web off in Settings. "Live" means it arrived while you were watching; "store" means it was published before Backpack started listening.

Settings

Install app updates automatically (on): repos are always checked; this decides whether app updates are then installed by themselves. Also check repositories' web addresses (off): the HTTPS fallback for the note. Only the note ever comes from the web.

Updates you didn't ask for, cancelled

Every download has a progress bar and a Cancel button. Cancel an automatic update and Backpack won't start that version again by itself. Apps Backpack installed update without a prompt on Android 12+.

Speed, honestly

Slower than a web server today, and we measured why

Storage's block exchange pays about a round trip per block, so speed depends more on distance than on bandwidth. Measured on 2026-10-23 with the same Storage build as the phone:

TestSpeed
Same file, same server, plain HTTP10.6 MB/s
Same file, Storage p2p, 64 KiB blocks (the default)58–120 KB/s
Same file, Storage p2p, 512 KiB blocks (what Backpack uploads now)200 KB/s → 200–500 KB/s on a phone
Two local nodes, 26 ms delay added, 1 node serving129–256 KB/s
Same, 3 nodes serving the same file454 KB/s, 6.0 MB/s, 6.3 MB/s

The last row is why mirrors matter. Each extra node serving a repo adds requests in flight, and with large blocks that compounds. Mirrors would be desktops and always-on boxes that keep a repo's CIDs (phones only fetch).

Publish

A repo from the command line

The CLI holds the repo key, uploads to a Storage node and signs everything. It can mirror an existing F-Droid repo after verifying it.

cd cli && npm install
./backpack.mjs init --name "My apps" --node http://<storage-node>:8080
./backpack.mjs import-fdroid https://example.org/fdroid/repo --fingerprint <SHA-256>
./backpack.mjs add my-app.apk --summary "…" --license MIT    # or add APKs directly
./backpack.mjs config --pointer-put 'exec:ssh box ./send.sh "$BACKPACK_KEY"'   # announce over Delivery
./backpack.mjs publish          # seq+1: index → Storage, note → Delivery (skips if nothing changed)
./backpack.mjs verify --deep    # check it all as a phone would

The repo key stays on the publisher's machine (mode 0600). Lose it and the repo can't be updated; leak it and someone else can publish as you. Key rotation is on the list below.

Status

What works, and what's next

Works today

Repos, signed indexes and notes; F-Droid import; installs with SHA-256 and signer checks; automatic updates; progress, cancel and uninstall; app detail pages; notes over Logos Delivery through Loam, with a 12-hour Store re-send; Settings. Backpack updates itself through Backpack.

Not yet

Mirrors ("I'm happy to serve these repos"). Key rotation and revocation, where a chain record (LEZ) is the candidate. A Wi-Fi-only switch. Background updates while the app is closed. Phones only (arm64); Delivery needs the Loam app installed.
